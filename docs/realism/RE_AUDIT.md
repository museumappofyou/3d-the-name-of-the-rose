### Confirmed code findings and unconfirmed risks

1. `people.js` creates 46 rigs: **20 monk, 5 novice, 9 servant, 4 herd, 4 peasant, 4 Abbot**. Full-office choir requests **36 monk + 6 novice** slots. `recycle()` falls back to any free rig without changing `makeFigure()`'s permanent kind. Role/dress mismatch is confirmed; visible identity swapping due to distance reordering is a risk requiring observation, not a claimed measured flicker.
2. `horarium.js` returns `work` phase during Terce/Nones while `officeAt()` returns an office. `schedule.js` checks only `phase.id === 'office'` for office choir. Sound receives office state independently. This is a source-confirmed discrepancy; verify final scene/sound together at 9.05 and 14.55.
3. Hospice `claustrum.js`: `h1 = 5.9`, floor top `h1 + 0.3`; `places.js` retains `walk.y = 4.2`; `spawnOf()` adds 0.05. Upper-zone threshold also predates the floor raise. Use existing builder anchor when correcting alignment.
4. Startup repeatedly emits six `Texture marked for update but no image data found` warnings. Origin and visual effect have not been established; do not label six assets as missing.
5. `outbuildings.js` `building()` adds the full floor when `floorMat` is set; `smithy()` requests `soil`. `smithyBasement()` adds another slab with `holes: [holeLocal]` but does not remove/omit the original. The stair geometry and cells are beneath a solid floor.
6. `schedule.js` puts smiths in an outdoor scatter area with no explicit floor y. `people.js` uses terrain/clear-ground resolution for those targets. Live forge workers visibly penetrate the built floor; use workstation/floor anchors before replacing their assets.
